    18→### Root cause of the inverted-controls bug
    19→Files 1 & 2 reinvent movement incorrectly instead of using the canonical
    20→`PointerLockControls.moveForward(d)` / `moveRight(d)` helpers (which project the local
    21→move onto the camera's true world forward/right vectors via the quaternion). The fix is
    22→to use those helpers.
    23→
    24→### Architecture of the new build
    25→- **Frontend**: Next.js `/` route. Lobby (name + skin + room list) → Game (Three.js canvas + HUD).
    26→  Uses `socket.io-client` connecting via `io("/?XTransformPort=3003")`.
    27→  Movement uses `controls.moveForward/moveRight` → **bug fixed**.
    28→- **Backend mini-service** (`mini-services/game-server`, port 3003): socket.io server with
    29→  rooms, player state sync (20 Hz), mob (PvE doodle enemy) sync, hit reporting, kills,
    30→  respawns, kill feed, scoreboard.
    31→- **Shared**: doodle aesthetic (paper background, black wireframe edges, hand-drawn fonts).
